2. STRENGTHENED VALIDATOR: PROPER NOUNS & GEMINI FAITHFULNESS CHECK
================================================================================

[ENHANCEMENTS IMPLEMENTED IN automation/fetchers/anilist.py]
The validation pipeline now enforces a two-layer verification on all Hindi synopses:

1. Deterministic Entity & Proper Noun Alignment:
   - Maintains an extensive catalog of canonical anime entities:
     `KNOWN_ANIME_ENTITIES` (Maomao, Jinshi, Shi Clan, Inner Palace, Verdigris, Loulan, Satoko, Shinpei, Takemichi, etc.).
   - Explicit Foreign Entity Rejection:
     If a Hindi synopsis contains any recognized named entity (e.g. "जिनशी" / Jinshi, "इनर पैलेस" / Inner Palace)
     that is NOT explicitly present in the English source text, the translation is IMMEDIATELY REJECTED.
   - Word-Boundary Regex Isolation:
     Uses regex boundary detection `(?<![\u0900-\u097f]){entity}(?![\u0900-\u097f])` for Devanagari and
     `\b{entity}\b` for Latin text to prevent partial substring false positives.

2. Automated LLM Faithfulness Auditor (`validate_faithfulness_with_gemini`):
   - Whenever `GEMINI_API_KEY` is present, the validator queries Gemini 1.5 with temperature 0.0:
     "You are a strict translation auditor. Compare the English source text and its Hindi translation.
      Question: Does the Hindi add, remove or contradict any fact vs the English source?
      Return ONLY valid JSON in format: {\"faithful\": bool, \"issues\": []}"
   - Rejection Criteria: If `faithful == false`, the translation is rejected and the raw English text
     is preserved with `translation_status = 'failed'`, scheduled for automated re-translation on the next run.
